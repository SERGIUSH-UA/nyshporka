# Прочитати справу на орендованій машині

Читання рукопису впирається в процесор: на звичайному ноутбуці справа на три
тисячі аркушів — це тиждень. На орендованій машині з кількома десятками ядер —
година-дві й один-два долари. Ця сторінка про те, як зробити це однією командою,
маючи лише ключ провайдера оренди й гроші на його балансі.

Якщо машина у вас уже є (свій сервер, робоча станція) — оренда не потрібна,
дивіться [кінець сторінки](#own-machine).

!!! warning "Малу справу везти нікуди не треба"
    Підготовка чужої машини займає близько восьми хвилин незалежно від обсягу.
    На сотні аркушів весь захід і буде цими вісьма хвилинами — `nysh read <тека>`
    удома вийде швидше й безплатно.

## Що потрібно

1. **Плагін оренди.** У самій Нишпорці оренди немає: кожен провайдер — це свій
   акаунт і своя тарифікація, тож оренду дає окремий пакет. Набір `rent`
   витягує його як залежність:

    ```sh
    pip install "nyshporka[rent]"
    ```

    Чи він стоїть, показує `nysh doctor` (рядок «Оренда») і
    `nysh cloud hosts list`.

    ⚠ На PyPI пакет оренди зветься `gpuhire`, а команда в терміналі —
    `gpurunner`: ім'я `gpurunner` на PyPI зайняв схожий проєкт. Тобто `pip`
    покаже одне ім'я, а `nysh doctor` — інше, і це не помилка.

2. **Акаунт у провайдера й гроші на балансі.** Для Vast.ai — реєстрація на
   cloud.vast.ai, поповнення від кількох доларів і ключ API (Account → API Keys).

3. **Ваги моделей** на вашій машині: `nysh models get`. Саме їх і везуть на
   орендовану. Рушій читання локально не потрібен.

## Три команди

### 1. Дати ключ

```sh
nysh cloud rent login
```

Ключ питається прихованим запитом і одразу віддається плагіну. Нишпорка його
не зберігає й не друкує; у теці дослідження ключа немає — її кладуть у хмарну
синхронізацію, і секрет звідти витік би назавжди.

Перевірити: `nysh cloud rent status` — ключ, баланс і що зараз тарифікується.

### 2. Подивитись, скільки це коштуватиме

```sh
nysh cloud go D:\скани\моя-справа --dry-run
```

Нічого не орендує. Звіряє кадри, складає план, питає ринок і друкує:

```
вилка $0.40–$1.10 · бюджет заходу $1.10 · стеля часу 4 год · рішення: …
```

- **Низ вилки** — прогноз ринку. **Верх** — той самий прогноз ×2.5: до першого
  читання невідомо, наскільки щільно списано аркуш, а щільний сповідний розпис
  читається вдвічі довше за метрику.
- **Бюджет заходу — це верх вилки.** Дійшовши до нього, захід сам зупиняється.
- Де Нишпорка пише **«невідомо»** — провайдер цього числа не дав. Вигаданих
  «типових» цін тут немає.

### 3. Прочитати

```sh
nysh cloud go D:\скани\моя-справа
```

Команда перевіряє кадри, збирає ваги з рушієм у дорогу, рахує кошторис — і
передає захід **наглядачеві**, після чого повертає вам термінал. Далі все йде
без вас: оренда → встановлення рушіїв на машину → заливка кадрів → читання →
забір тексту → звірка, що прочитано кожен аркуш → гасіння машини → оновлення
реєстру справ і пошукового індексу. Текст лягає туди ж, куди й після звичайного
`nysh read`.

Тому останній рядок команди — `detached`, а не «готово»: роботу почато. Як
справи й скільки вже витрачено:

```sh
nysh cloud state
nysh cloud stop      # якщо передумали
```

`stop` не обриває роботу на півслові: він просить наглядача **згорнути**
захід — той спиняє читання, забирає вже прочитане, звіряє його й гасить
машину. Прочитане лишається на диску, і та сама команда пізніше дочитає решту.

Замість теки можна дати шифру справи, якщо справа є в бібліотеці.

### Кілька справ одним заходом

```sh
nysh cloud go D:\скани\справа-1 D:\скани\справа-2 D:\скани\справа-3
```

Справи стають у чергу на ОДНІЙ машині. Це дешевше, ніж три окремі заходи:
машину треба знайти на ринку, оплатити її підняття й поставити на неї рушії —
приблизно п'ять хвилин оренди щоразу, і за чергу ви платите це один раз.

Що варто знати про чергу:

- **прочитана справа випадає з неї**, а решта їде далі. Причину ви побачите
  рядком у виводі;
- **справа, яку вже читає інший захід, спиняє всю команду** — машина ж одна, і
  брати другу під ту саму роботу немає сенсу;
- **спинити одну справу з черги не можна**: `nysh cloud stop` згортає весь
  захід, і команда про це попереджає;
- у машинному виводі (`--json`) кожна справа лежить окремим записом у `cases`;
  верхні поля про одну справу при цьому порожні — щоб їх не прочитали як
  відповідь про весь захід.

!!! warning "«Перечитати» тією самою моделлю в хмарі виходить не завжди"
    Машина зберігає точки відновлення, щоб після її раптової смерті читання
    продовжилось із місця, а не з нуля. Ключ цих точок несе **модель** — тож
    повторний захід тією самою моделлю знайде їх і просто підніме готове
    замість читати. Ви заплатите лише за доставку, і це зазвичай саме те, чого
    хочеться; але якщо треба справді перечитати **начисто**, беріть іншу
    модель (`--model`) — у неї свій ключ, або приберіть старі точки зі сховища.

    Побачити різницю можна в `nysh cloud state`: там окремо видно, скільки
    сторінок прочитано САМЕ В ЦЬОМУ прогоні.

### Перечитати справу іншою моделлю

Буває, що кирилична на вигляд справа наполовину написана латинкою — або
з'явилась новіша модель. Тоді:

```sh
nysh cloud go D:\скани\моя-справа --model latin
```

Результат лягає в окрему теку (`моя-справа-skryba_v6`), тексти першого прогону
лишаються цілими. Найдорожче в сторінці — розмітка рядків, і вона вже
порахована першим прогоном: Нишпорка знаходить її, перевіряє, що вона знята
саме з цих кадрів, і везе на машину. Сторінка тоді коштує лише розпізнавання —
удвічі дешевше.

Те саме на своїй машині: `nysh read D:\скани\моя-справа --model latin`.

!!! warning "Якщо розмітку взяти не звідти"
    Розмітка рядків не знає, з якого зображення її зняли. Візьміть її від
    кадрів іншого розміру — і рядки виріжуться не з тих місць: помилки не
    буде, текст вийде, і він буде неправильний. Саме тому Нишпорка звіряє
    розміри кадрів перш ніж щось везти, і відмовляється від розмітки, яка не
    збіглася, — кажучи про це вголос.

!!! note "Об'єктне сховище не обов'язкове"
    Якщо його немає, дані поїдуть на саму машину: Нишпорка покладе туди кадри
    й ваги по SSH, а машина роздаватиме їх собі сама. Нічого налаштовувати не
    треба — це вибирається автоматично; примусово: `--transport box`.
    Єдина різниця, яку варто знати: точки відновлення при цьому лежать на тій
    самій машині, тож Нишпорка забирає їх додому кожні п'ять хвилин, і після
    раптової смерті машини читання продовжиться майже з місця, а не з нуля.

!!! tip "Якщо хочеться, щоб команда вела все сама"
    `nysh cloud go … --thin` не передає захід нікому: команда сама тримає
    з'єднання з машиною до кінця прогону й показує поступ рядками. Вона живе
    рівно стільки, скільки живий термінал, — зате наглядач їй не потрібен.
    Читання на **своїй** машині по SSH — це окремі команди, `nysh cloud start`
    і далі; `go` там не працює, бо він про оренду.

## Як бережуться гроші

**Стеля автозапуску.** Без вашого слова захід стартує, лише коли верх вилки не
перевищує стелі — типово $2. Дорожчий захід відмовляє й просить `--confirm`.
Змінити стелю: `nysh cloud rent ceiling 5`.

**Дві стелі під час роботи** — гроші й години. `--budget` і `--max-hours`
задають їх самі; без них беруться верх вилки й потрійний прогноз часу. На
стелі читання зупиняється, **прочитане забирається**, машина гаситься.

**Машина гаситься завжди** — після успіху, відмови, помилки, Ctrl+C. Перед
гасінням Нишпорка намагається забрати все, що на машині вже прочитано.

**Нічого не читається двічі.** Якщо захід зупинився на стелі, повторіть ту саму
команду: уже прочитане поїде на нову машину готовим, а кошторис порахується
лише на решту.

**Кадри перевіряються до оренди.** Обірваний файл, тека, яка ще завантажується,
кадрів менше, ніж знає бібліотека, справа, вже прочитана цією моделлю, — усе це
відмова до першого цента.

**Завеликі кадри стискаються.** Скани по 6–12 МБ не роблять читання точнішим,
але їдуть на машину вп'ятеро довше — а вона в цей час уже тарифікується. Якщо
медіана кадру понад 3 МБ, на машину їде сіра копія висотою 3100 пікселів;
оригінали не чіпаються, і після читання справа посилається саме на них.

!!! danger "Після кожного заходу — одна перевірка"
    ```sh
    nysh cloud rent status
    ```
    Вона питає провайдера напряму й бачить навіть машину, про яку Нишпорка не
    знає. Якщо захід скінчився словами **«МАШИНУ НЕ ВДАЛОСЬ ПОГАСИТИ»** —
    виконайте `nysh cloud stop <захід> --force`, перевірте ще раз, і якщо
    машина лишилась, погасіть її в кабінеті провайдера. Це єдиний випадок,
    коли гроші йдуть без нагляду.

## Якщо закрився термінал

Нічого страшного, і навіть не треба нічого робити: захід веде наглядач, і від
вашого вікна він не залежить. Відкрийте термінал і спитайте `nysh cloud state`
— він покаже, де захід зараз.

!!! warning "Комп'ютер вимикати не можна"
    Наглядач — окремий процес **на вашій же машині**, а не в хмарі. Вимкнений
    чи приспаний комп'ютер означає, що стежити за орендою нікому: вона
    горітиме, доки не спрацює запобіжник провайдера. Закрити вікно — можна;
    вимкнути машину — ні, поки захід не скінчився.
Повторна `nysh cloud go` тієї самої справи другої машини не візьме: вона
побачить живий захід і скаже про нього.

Інакше лише з `--thin`: там стелі грошей і годин стереже сама команда, тож поки
вона не працює, лишається страховка провайдера — машина знищить себе сама за
годину після стелі часу.

Кілька справ одночасно з різних терміналів — можна: кожен захід має свою
машину й не бачить чужих.

## Коли щось не так

| що сталось | що це означає |
|---|---|
| «потрібен --confirm» | захід дорожчий за стелю автозапуску. Подивіться вилку й вирішіть |
| «на рахунку $…, а верх вилки $…» | поповніть баланс у провайдера |
| «ринок порожній» | зараз немає машини під ваші стелі. Пізніше або вища `--max-price` |
| `budget_stop`, `deadline` | спрацювала стеля. Прочитане збережено — повторіть команду |
| `incomplete` | бракує кількох аркушів навіть після догону. Дочитайте вдома: `nysh read <тека>` |
| «письмо не визначається» | гляньте перший скан і додайте `--script cyrillic` або `--script latin` |
| заливка йде дуже довго | у системі немає `scp` (захід скаже про це). У Windows 10 і новіших він є: «Додаткові компоненти» → «Клієнт OpenSSH» |

## Своя машина { #own-machine }

Якщо є сервер із доступом по SSH, оренда не потрібна. Кроки ті самі, але
окремими командами, і нічого не вирішується без вас:

```sh
nysh cloud hosts add дім ivan@192.0.2.10 --key ~/.ssh/id_ed25519
nysh cloud prepare дім
nysh cloud plan D:\скани\моя-справа --host дім
nysh cloud start D:\скани\моя-справа --host дім
nysh cloud state
nysh cloud fetch
nysh cloud verify
nysh cloud stop
```

Для агента весь порядок, із приймачами кожного кроку, описано в скілі
«читання на чужій машині» — див. [«Підключити агента»](agent.md).
