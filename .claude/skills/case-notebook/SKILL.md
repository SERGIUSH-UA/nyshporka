# Нотатник справи

**Вхід** — те, що дізнались про справу понад машинний текст: рядок, звірений
на кропі; справжній зміст книги; розбіжність з описом архіву; копія в іншому
фонді. **Вихід** — записи в `data/pages/<архів>/<справа>.json` (секція
`notes`, той самий файл, що й переглянуті аркуші) і, з дозволу людини, — у
нотатнику книги в Супрязі.

## Що куди

| що | куди |
|---|---|
| переглянутий аркуш: тип, прізвища, статус | `nysh pages note` (скіл `keep-records`) |
| рядок, звірений оком на кропі | `nysh note read` |
| що в справі насправді, роки, парафії | `nysh note add --kind about` |
| опис архіву помиляється (назва, роки, шифра, обсяг) | `nysh note add --kind catalog-error` |
| копія, чернетка, примірник, продовження деінде | `nysh note add --kind copy` |
| родинне, гіпотези про рід, «не наш» | `nysh note add --kind note` — лише вдома |

Межа між загальним і особистим одна: **чи корисне це кожному, хто відкриє цю
справу**. «Копія цієї книги — ДАВіО 904-24-55» — так. «Тут хрестили мого
прадіда» — ні. Вердикт «не наш рід» — теж ні: він про ваш рід, а не про
справу.

## Звірене оком читання рядка

```bash
nysh text crop <справа> <сторінка> <рядок>          # кроп для ока
nysh note read <справа> <сторінка> --line N --text "<дослівно>" \
    [--confidence high|medium|low] [--uncertain "слово,слово"] [--model <модель>]
```

Прогін, рамку рядка й те, що прочитав рушій (`was`), команда бере сама.
Номер рядка — як у `nysh text ctx` (з одиниці) і має сенс лише в прогоні, на
який записано: пошук показує читання поряд із рядком тільки на тій самій
нарізці.

🔴 **Текст — дослівно, як на аркуші**, з дореформеною орфографією. Тлумачення
(«це той самий Іван, що в ревізії») — окремим записом `note`.

🔴 **Нотатник — не голос.** `text find` показує його окремим каналом
«notebook»; у знаменник справи він не йде, і відсутність збігу в ньому нічого
не означає: око читало вибрані рядки.

## Виправити, позначити, відкликати

Журнал лише дописується. Виправлення — новий запис:

```bash
nysh note add <справа> --kind about --text "…" --supersedes <uid>
nysh note share <справа> <uid…>          # позначити до віддачі
nysh note share <справа> <uid…> --home   # повернути додому
nysh note retract <справа> <uid…>        # відкликати
nysh note list <справа> [--history] [--from own|pool]
```

## Віддати в Супрягу

```bash
nysh note push <справа> --dry-run        # що поїде, що не пустять ворота
nysh note push <справа>                  # після згоди людини
```

Їде: записи, позначені `--share` / `note share`, і переглянуті аркуші без
коментарів (прізвища — лише з аркушів `status=full`). Не їде ніколи: `note`,
автор запису, ім'я сесії, коментарі аркушів.

🔴 **`push` — від імені людини й з її ключем.** Агент показує `--dry-run` і
питає; сам не відправляє.

🔴 **Ворота ті самі, що в пулі.** Запис із «мій дід», «наш рід», «прабаба»,
посиланням канону `[[…]]`, поштою чи телефоном не пройде. Не обходити
переформулюванням: розділити на загальне (`about`) і особисте (`note`).

Нотатник дописується лише до книги, яка в Супрязі вже є. Немає книги —
спершу текст (`share-case`).

## Чуже з пулу

```bash
nysh note pull <справа>
```

Чужі записи лягають з позначкою походження й лише для читання. Рамка рядка
лишається тільки там, де чужий прогін лежить у вас із прив'язкою `exact`;
інакше запис текстовий. Чужий нотатник, як і свій, нуля не дає.

## Вільні теки звірки оком

```bash
nysh note import-eye reports/htr/<прогін>-claude_eye --model <модель> --dry-run
nysh note import-eye reports/htr/<прогін>-claude_eye --model <модель>
```

Блоки `[рядок N] …` стають читаннями рядка, примітки — домашніми `note`. Усе
лягає домашнім: що з цього віддавати, вирішує людина. Повторний імпорт не
дублює. Нерозпізнані рядки названо у відповіді — вони лишились тільки в теці.
