# Куди копати: від питання до каналу

**Вхід** — питання людини: село, парафія, рід, особа, фонд, справа, період.
**Вихід** — план заходу: канали по порядку, приймач кожного, ціна, правило
зупинки, і що вже прочесано. Довідник — три файли в `references/` (копії
`docs/agents/` пакета), і читати їх треба не всі одразу:

| файл | що там | коли |
|---|---|---|
| `where-to-dig.md` | протокол, класи каналів, баланс, власні знання, заведення каналу | завжди, спершу |
| `where-to-dig-genres.md` | десять жанрів: канали по порядку, стоп, пастки | той жанр, у який зайшов |
| `where-to-dig-channels.md` | картки каналів: дає / не дає / ціна / знаменник нуля | картки каналів із плану |

Скіл не виконує канали — він їх обирає й передає естафету: село → `find-parish`,
фонд → `keep-fond`, прізвище в прочитаному → `find-surname`, зйомка ззовні →
`take-delivery`, облік → `keep-records`.

## Крок 0 — оверлей простору

Якщо існує `<простір>/reports/research/where-to-dig.md` — прочитати його
**після** довідника. Там дослідник тримає свої фонди, шифри, маршрути доступу,
ціни й реєстр прочесаного за тими самими жанрами. Немає — працюй за
довідником і не питай про нього.

⚠ Свої заміри й пастки дописуй в оверлей, не в цей файл: правлений руками
скіл не оновлюється разом із пакетом.

Людина дала посилання на статтю або пост «де що лежить» — це позиція, не
факт: копія в `<простір>/data/raw/refs/` з паспортом → твердження рядками →
звірка каталогом числом → у маршрут жанру оверлею з поміткою «за <автор
рік>» → рядок у реєстрі статей. Порядок — розділ «Стаття-підказка» довідника.

## Крок 1 — жанр питання

Один із десяти в довіднику: метрики села · унійна доба · шляхетство ·
духовенство · податний стан · XX ст. · контекст села · «ми це вже знаємо?» ·
людина/контакт · шифра відома. Два жанри — лише з поясненням, чому.

Регіон, повіт, єпархія, конфесія — з профілю простору:

```bash
nysh profile show --json        # поле places: назва, історична назва, повіт, єпархія, конфесія
```

Порожньо — спитати людину один раз і запропонувати вписати в профіль, щоб
наступна сесія не питала знову.

## Крок 2 — гіпотеза з голови, ДО запитів

Одним блоком «З голови: …»: якій установі належало село в цю добу, які жанри
документів вона вела, де вони мали осісти. Це записується як гіпотеза і йде
на перевірку каталогом. 🔴 З пам'яті не беруться номери фондів, роки, аркуші,
ціни, шляхи, `caps` і команди — лише з каталогу, реєстру, `nysh op sources.list`,
`nysh op <ім'я> --describe`.

## Крок 3 — що вже є, локально

```bash
nysh text index                          # один раз на свіжому просторі: без нього grep відмовляє
nysh text grep "<ключ>" --where all      # канон, описи, нотатки: layers.coverage по шарах
nysh cases list                          # що на диску, прочитано, прошукано; stale
nysh pages status <справа>               # що бачило око
nysh geog find "<село>"                  # де документи села по всіх фондах
```

⚠ `nysh text grep` на просторі без текстового стору відповідає `ok: false` із
`next: text.index` — і не шукає тоді навіть канону й нотаток. Ключ `stale` є
лише в застарілого реєстру (`stale.is: true`); на свіжому його немає взагалі,
і це «свіжий», а не «невідомо».

→ розділ плану «Що вже прочесано» зі знаменником по кожному шару. Якщо в
просторі є реєстр прочесаного (оверлей, розділ «більше не повертатись») —
прочитати перед тим, як пропонувати канал.

## Крок 4 — які канали реально підключено

```bash
nysh op sources.list                     # id, caps, about (клас, межі, що доводить нуль), undeclared
```

Кожен `id` → клас із `about.where_class`, межі з `about.scope` — проти місця й
доби питання. Джерело, яке за побудовою не накриває регіон, у плані стоїть
позначкою «поза покриттям», а не зникає. Джерело без `search` у `caps` не
пропонується як пошукове. Джерело з `undeclared` або без картки — рядок «без
опису — перевірити руками», не викинуте. Клас без вбудованого джерела —
«руками», з карткою довідника. Веб-пошук — окремий рядок плану, за правилами
його картки.

## Крок 5 — перший зовнішній замір і естафета

```bash
nysh find "<село або шифра>"             # без --source: одне віяло по всіх, знаменник і тип нуля кожного
```

`--source` — лише щоб повторити один канал іншим написанням. Що доводить нуль
кожного джерела, читається з `coverage.zeros` (у терміналі — рядки
`0 · <id>: …`).

Шифра в запиті йде адресним маршрутом (`address_route` у попередженнях —
текстового пошуку по каталогах не було). Далі за жанром довідника: село →
`find-parish` чотирма каналами; фонд → `keep-fond`; XVIII ст. → `nysh church find`.

## Крок 6 — план заходу (форма виходу)

| # | канал (клас → id) | запит | приймач | ціна | правило зупинки |
|---|---|---|---|---|---|

Плюс три рядки: «Що вже прочесано» (шари, знаменники), «Нуль означає …»
(що саме доведено, коли всі канали дали нуль), «Далі» (наступний канал після
нуля і чи потрібне рішення людини).

🛑 Платне — замовлення в архіві, платний дослідник, оренда машини — у плані з
ціною, і без підтвердження людини не запускається.

## Крок 7 — записати

Переглянуте → `keep-records`. Гіпотезу й нуль → нотатка простору зі
знаменником. Канал, який дав нуль утретє або заблокований, → рядок у реєстрі
прочесаного оверлею: канал · що шукали · результат · дата · причина.

## Перед тим, як сказати «немає»

1. Крок 3 виконано командами, а не з пам'яті.
2. Названо, які класи прогнано і які ні — і чому ні.
3. Чи впирались у стелю видачі якогось джерела.
4. Який канал наступний і скільки він коштує.
5. Блок «З голови» є, і в ньому видно, що мало існувати й де перевірено.
6. Тип кожного нуля названо: не шукали · поза покриттям · шукали й немає ·
   обрізано · однойменець (розділ «Типи нуля» довідника).
