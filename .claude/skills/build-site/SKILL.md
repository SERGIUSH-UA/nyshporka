# Сайт роду з канону

**Вхід** — канон, який проходить `nysh canon check` без помилок. **Вихід** —
тека `<простір>/site/private/html` або `<простір>/site/public/html` зі статикою,
яку можна відкрити в браузері чи викласти на хостинг.

Потрібен MkDocs: `pip install nyshporka[site]` (без нього команда скаже саме це).

## Головне

- 🔴 **Відкрита версія (`--public`) — для публікації**: живих і близьких до
  живих там немає взагалі, а готовий HTML перевіряє сторож; витік — відмова, і
  HTML видаляється (крок 3).
- 🔴 **Пакет лише збирає теку зі статикою; викладає її людина** («Куди
  викласти»).

---

## Крок 1 — канон цілий

```bash
nysh canon check
```

На помилках збірка відмовиться: сайт із битими зв'язками бреше. Попередження
`maybe_living` — особа без смерті, народжена за останні 100 років, без
`private: true`. У приватній версії її дати й нотатки будуть видні повністю, тож
спитай людину й познач `private: true` (скіл `keep-canon`).

## Крок 2 — яка версія

| версія | для кого | живі |
|---|---|---|
| приватна (`nysh site build`) | сам дослідник, родина за паролем | є, дати до десятиліття, без фото й нотаток |
| відкрита (`nysh site build --public`) | будь-хто в інтернеті | немає зовсім: ні сторінок, ні імен у дереві, ні сканів |

🔴 **Викладати в інтернет — лише відкриту.** Приватна несе повне дерево
(`tree.full.json`) для локального перегляду.

Хто прихований у відкритій версії: `private: true`; без смерті й народжені від
`born_after` (1920); померлі від `died_after` (2000) — у них найближчі живі;
особи без жодного року — за родиною; поіменно `extra_hide`. Пороги й винятки —
`data/site/site.yml`.

## Крок 3 — зібрати й подивитись

```bash
nysh site build --public
nysh site serve --public        # http://127.0.0.1:8765/
```

**Приймач відкритої версії:** команда закінчилась ✅, а не ⛔ «називає
прихованих». Сторож шукає в готовому HTML і пошуковому індексі імена й ID
прихованих; знайшов — HTML видаляється, і перелік витоків названо поіменно.
Витік зазвичай сидить у рукописній сторінці з `overlay/`: виправ текст там, а не
послаблюй пороги.

Попередження `namesakes` — тезки прихованих серед опублікованих: їхні імена
пробою не стали, тож перегляд цих сторінок оком обов'язковий.

**Що показати людині після збірки:**
- **Дерево.** Розкладка «пісочний годинник» навколо однієї особи: предки вгору,
  нащадки вниз, подружжя в тому ж ряду, брати й сестри обабіч. Тап по картці
  відкриває деталі, ще один тап робить особу центром. Посилання на конкретну
  особу: `family-tree.html#<ID>`. Кнопки ▲/▼ задають, скільки поколінь
  показати.
- **Телефон.** Деталі виїжджають шторкою знизу; дерево, мапа й граф
  рухаються й масштабуються пальцями. Перевіряй вузьким вікном браузера (~390 px),
  а не лише широким.
- **Гіпотези.** Кожна картка гіпотези має свою сторінку (`hypotheses/H….html`)
  і стоїть на сторінках осіб і родин з `about`. Відкрита версія не публікує
  гіпотезу, яка зачіпає хоч одного прихованого, тож у ній гіпотез менше, ніж
  у приватній. Це не вада.
- **Особа без сторінки.** Якщо особа є в пошуку дерева, але сторінки не має,
  вона прихована у відкритій версії. Це не вада.

Дерево на телефоні не підганяє весь рід під екран: воно тримає читабельний
масштаб на особі у фокусі. Решту видно, якщо посунути полотно.

## Без термінала: консоль і ярлик

Людині, яка не працює в терміналі, не диктуй `nysh site build`. Є коротший шлях:
1. Консоль Нишпорки → «Дослідження» → «Сайт родини».
2. «Зібрати» або «Перезібрати». Збірка йде роботою з поступом, її видно й у
   «Роботах».
3. «Відкрити сайт». Сайт віддає сама консоль на `/site/` (відкрита версія — на
   `/site-public/`), окремого сервера тримати не треба.

Ярлик «Сайт родини» на робочому столі виконує `nysh serve --page site`: він
піднімає Нишпорку або відкриває вкладку у вже запущеній.

## Мови

Сайт збирається сімома мовами (uk, en, pl, ro, fr, de, ru) з перемикачем у
шапці.
- Перекладається оболонка: меню, заголовки, події, дати, дерево, мапа. Імена,
  факти й нотатки лишаються мовою канону.
- Кожна мова — окрема збірка, тож великий родовід збирається довше. Якщо
  людині потрібні не всі мови, впиши в `site.yml` `languages: [uk, en]`.
  Основна мова — `language`.

## Налаштування: `data/site/site.yml`

Усе необов'язкове: назва й опис, пороги приватності, групи місць для переліку
й мапи (`place_groups` з підрядками адмінподілу), епохи мапи (`eras`), власні
пункти меню (`nav_before`, `nav_after`). Власні сторінки — історії, гілки —
кладуться в `data/site/overlay/` і перекривають згенеровані з тим самим іменем.
Повний перелік полів — у докстрінгу `nyshporka.site.config`.

Простір, що збирає MkDocs сам (свій `mkdocs.yml`), бере оформлення з пакета:
`nyshporka.site.build.install_assets(docs)` і `write_pages(...)`. Власні копії
`assets/css`/`assets/js` пакетних файлів не тримати, бо вони розходяться з
пакетом.

## Куди викласти

Пакет не деплоїть. Тека `html` — звичайна статика: GitHub Pages, Cloudflare
Pages, Netlify, власний сервер. Приватну версію — лише за авторизацією
(наприклад, Cloudflare Access) або локально.
