# Читання справи на чужій машині

**Вхід** — справа (тека кадрів або шифра з бібліотеки). **Вихід** — текст у
теці прогону, сторінок із текстом стільки ж, скільки кадрів, справа видима в
обліку, машина відпущена, на акаунті нічого не тарифікується.

Читати на цій машині — скіл `read-case`. Мала справа (сотні кадрів) — теж туди:
холодний старт чужої машини коштує близько восьми хвилин незалежно від обсягу.

Темп, пам'ять, сховище R2, транспорт, вибір машини, черга, партія `--boxes`,
друковані видання й таблиця збоїв — `references/cloud-reading.md`.

🔴 Прапорців, яких немає в `nysh cloud go --help`, не вигадувати.

## Головне

- 🔴 **Гроші вирішує людина.** Старт понад стелю автозапуску — лише з її
  `--confirm` (А2). Після кожного заходу звірити, що нічого не тарифікується
  (А3).
- 🔴 **Порядок `fetch → verify → stop` непорушний:** спершу забрати, потім
  звірити, лише тоді відпустити машину, бо недочитане лежить на ній.
- 🔴 **Приймач повноти — диск і покадрова звірка**, а не код повернення: буває,
  що лог обірвано, перелік збоїв порожній, а процес виходить нулем.
- **Що шукати в машині, залежить від голосів.** З одним голосом Писаря — ядра;
  з PP-голосом (Дяк-Літописець, Скриба PPv3) — карту з тензорними ядрами, і тоді
  допомагає менше моделей, а не більше шардів.

Шляхів два: машини немає — **оренда** (А), машина є — **своя** (Б).

## А. Оренда

Оренду дає пакет-плагін. Що стоїть — `nysh cloud hosts list` (рядок з `rent`) і
`nysh doctor` (рядок «Оренда»). Немає — `pip install "nyshporka[rent]"`.

### А0 — ключ, один раз

```bash
nysh cloud rent login       # ключ питається прихованим запитом
nysh cloud rent status      # ключ, баланс і що ЗАРАЗ тарифікується
```

🛑 **Ключ дає людина.** Не проси вставити його в чат і не передавай через
`--key`: прапорець лишається в історії оболонки.

Сховище R2 (кадри їдуть один раз, переоренда підхоплює роботу сама) —
`nysh cloud rent storage`, порядок у довіднику. Ключі сховища теж від людини.

### А1 — сухий прогін, який нічого не коштує

```bash
nysh cloud go <справа> --dry-run
```

Звіряє кадри, стискає завеликі, складає план, питає ринок і друкує вилку
кошторису з рішенням. Кадрів і ваг не заливає (`--dry-run --stage` — залити й
лишити план готовим).

- **Вилка `$низ–$верх`:** низ — прогноз ринку, верх — він же ×2.5. **Бюджет
  заходу = верх**, на ньому захід сам зупиниться.
- **Щільність** (рядків на сторінку): з попереднього прогону; у партії — медіана
  прочитаних справ того самого опису (перед партією свіжий `nysh cases build`);
  одиночна нечитана справа — вибірка 40 кадрів. Звідки цифра — рядок `density`.
- **Рішення:** верх ≤ стелі автозапуску (типово $2) — захід стартує сам; понад
  неї — потрібен `--confirm`.
- **«Невідомо»** означає, що бекенд числа не дав. Не підставляй своє.
- 🔴 **Письмо мусить бути визначене** (`--script cyrillic|latin`), якщо план
  каже «не визначається»: невідповідний рушій збою не дає, текст просто
  виходить хибним. Мішане письмо — `--with latin`.
- 🔴 **Відмова до оренди — це робота, а не перешкода.** Битий кадр, тека, що ще
  качається, кадрів менше, ніж знає бібліотека, «вже прочитано»: кожна з них
  після оренди коштувала б грошей. `--allow-partial` і `--rerun` — рішення
  людини; скажи їй, чому захід відмовив.

### А2 — захід

```bash
nysh cloud go <справа>                 # у межах стелі автозапуску
nysh cloud go <справа> --confirm       # 🛑 лише з дозволу людини
nysh cloud go <справа> <справа> …      # кілька справ — одна черга, одна машина
```

- 🛑 **`--confirm` — слово людини.** Код 10 означає «дорожче за стелю»: покажи
  вилку й спитай. Підняти стелю назавжди (`nysh cloud rent ceiling <сума>`) —
  теж її рішення.
- Захід веде **відчеплений наглядач**: оренда → рушії → заливка → читання під
  двома стелями (гроші й години) → забір → звірка → догін малого хвоста →
  гасіння → `cases build` і `text index`. Вердикт `detached` (код 0) означає
  «пущено», а не «текст на диску»: далі — `nysh cloud state`.
- Вікно термінала після `detached` можна закривати: наглядач від нього не
  залежить. Машину — ні: наглядач живе саме на ній. Що буде, якщо її вимкнути,
  — довідник, розділ «Транспорт і повільний канал».
- 🔴 **`cloud go` — поза пісочницею агента**, з дозволу людини на цей виклик.
  Пісочниця після виклику вбиває все, що він лишив у фоні, тобто й наглядача,
  а машина горить далі. Після `detached` окремим викликом перевір
  `nysh cloud state <захід>`: фаза мусить рухатись.
- Процеси `python` масово не вбивай: лише конкретний PID і з дозволу людини.
- Кілька справ — одна черга: холодний старт платиться раз. Вердикт тоді — про
  захід; правда по справах — у `cases[]` і `dropped[]`, і разом вони мусять
  дати всі названі справи.
- Великий обсяг із дозволом на всю суму — партія на кількох машинах:
  `--boxes N` (одна машина на ~10–15 тис. сторінок). Власного диспетчера оренд
  не писати: спільну стелю й стан партії тримає лише `--boxes`.
- Друковане видання (газета, журнал) — `--print`; рукописний рушій друк не бере.
- Друкований бланк, заповнений від руки (акт РАЦС, анкета) — `--form-cells`
  (або поле `form` у паспорті справи — тоді сам): ще голос `<прогін>-cells`
  тим самим проходом; сторінка без сітки лишає позначку, і звірка повноти її
  рахує. Як це працює й чим міряти — скіл `read-case`.
- Агентові — `--json`: останній рядок виводу — один об'єкт (`verdict`,
  `pages_done`, `pages_total`, `spent_usd`, `released`, `out_dir`, `run_id`,
  `notes`, `cases`, `run_ids`).

| код | вердикт | що робити |
|---|---|---|
| 0 | `ok` | справа прочитана; далі пошук |
| 0 | `detached` | захід веде наглядач — `nysh cloud state` |
| 2 | `refused` | відмова до оренди — причина в `why` |
| 3 | `failed` | збій; що встигло — забрано |
| 4 | `incomplete` | бракує сторінок і після догону; малий хвіст — `nysh read <тека>` вдома |
| 5 | `budget_stop` | стеля грошей; прочитане збережено |
| 6 | `market_empty` | немає машини під ціль темпу (чекали до години): пізніше; причини — у `why` |
| 7 | `deadline` | стеля годин; прочитане збережено |
| 8 | `no_credit` | на рахунку менше за верх вилки — поповнює людина |
| 9 | — | 🔴 машину НЕ погашено — А3 |
| 10 | `needs_confirm` | потрібен дозвіл людини |
| 11 | `partial_start` | партія пущена не вся; пущені черги не гасити |
| 12 | `search_quota` | провайдер відмовив у пошуку до скидання квоти — повторити після часу з `why` |
| 13 | `slow_uplink` | доставка з дому з'їла б понад чверть оренди — вибір людини: R2, менша порція чи `--accept-slow-delivery` |
| 130 | `cancelled` | перервано; прочитане забрано, машину погашено |

🔴 **Після `budget_stop`, `deadline` чи `incomplete` — та сама команда ще раз.**
Прочитане рушій пропускає, кошторис іде лише на решту.

🔴 **Після обриву термінала — теж та сама команда.** Повторний `go` підхоплює
свій захід разом зі стелями й другої машини не бере. Поки термінал закритий,
стелі не стереже ніхто з нашого боку (бокс знищить себе сам через
`max_hours + 1` годину), тож захід підхоплюй одразу.

### А3 — приймач грошей, після КОЖНОГО заходу

```bash
nysh cloud rent status        # код 3 — щось тарифікується поза заходами простору
nysh cloud state --all        # заходи, що ще тримають машину
```

- 🔴 **«Невідомо» — не «нічого».** Не вдалось спитати провайдера — повтори; не
  звітуй людині «все погашено».
- 🔴 **Код 9 / «МАШИНУ НЕ ВДАЛОСЬ ПОГАСИТИ»:** одразу
  `nysh cloud stop <захід> --force`, знову `rent status`; машина лишилась —
  людина гасить її в кабінеті провайдера. Іншу роботу не продовжувати, доки це
  не закрито.
- Щойно зупинений бокс API показує не одразу: `rent status` ще раз за кілька
  хвилин.

## Б. Своя машина: дрібними кроками

Сервер чи бокс, до якого вже є SSH. Тут нічого не вирішується саме.

```bash
nysh cloud plan <тека> --host <машина>     # без мережі й без витрат
nysh cloud hosts add <ім'я> <user@host[:порт]> --key ~/.ssh/id_ed25519
nysh cloud prepare <ім'я>                  # середовище рушіїв, раз на машину
nysh cloud start <тека> --host <машина> --script cyrillic
nysh cloud state
nysh cloud fetch
nysh cloud verify
nysh cloud stop
```

- **Приймач плану:** названо шифру справи. Без неї прогін ляже «нічиїм».
- 🔴 **Ключ SSH записується шляхом**, ніколи не вмістом і не паролем: файл
  машин лежить у теці простору, яку кладуть у git і хмарну синхронізацію.
- `start` повертається одразу. Після обриву — та сама команда з тими самими
  прапорцями (разом із `--with`): вона підхопить свою роботу.
- 🔴 **`fetch` і `verify` — два кроки.** Хвіст малий (до ~2 % і до ~сотні
  сторінок), а машину вже відпущено — доганяти вдома `nysh read <тека>`.
  Бракує багато — машину не гасити: недороблене лежить на ній.
- 🔴 **`stop` відчепленого заходу ЗГОРТАЄ його:** наглядач спиняє читання,
  забирає, звіряє й гасить машину сам. `--force` убиває наглядача, і машину
  тоді нікому гасити.
- 🔴 **`stop` відмовиться, поки роботу не звірено**, і це правильно. Кинути
  захід свідомо — `--force`.

Скільки процесів, сховище для десятків гігабайтів, `scp` — довідник, розділ
«Своя машина».
