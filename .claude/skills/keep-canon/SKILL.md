# Канон роду: картки правиш ти, пакет перевіряє

**Вхід** — знахідка, яку людина підтвердила (або гіпотеза, яку просили
записати), чи файл GEDCOM для порожнього простору. **Вихід** — картки в
`data/canonical/`, які проходять `nysh canon check`, і свіжа база роду.

Формат картки, рубрика `confidence`/`status` і правила зв'язків — у
`references/canon.md`. Прочитай його перед першою правкою в сесії.

## Головне

- 🔴 **Команд «додай особу» немає навмисно**: картку правиш ти файлом, пакет
  лише перевіряє (`canon check`), індексує (`canon index`), видає ID
  (`canon new-id`), засіває з GEDCOM (`canon import`) і кладе докази
  (`evidence add`).
- 🔴 **Канон читати ПЕРЕД внесенням** (крок 1): більшість «знахідок» у ньому
  вже є.
- 🔴 **Вердикт «це наш рід» виносить людина** (крок 2).
- 🔴 **Цифра чи дата з декоду — в канон лише після звірки з зображенням**
  (крок 2).
- 🔴 **Доказ-кроп у постійний стор ДО факту** (крок 3), бо цитата на тимчасовий
  файл провисає, коли його чистять.
- 🔴 **Недоведене — карткою гіпотези `H…`, а не в нотатках** (крок 2½). Що
  людині вирішити, видає `nysh canon next`; більше трьох рішень за раз не
  показувати.

Порядок: прочитати канон → доказ у стор → ID з `nysh canon new-id` → правка
картки → `nysh canon check` і `nysh canon index`.

---

## Крок 0 — порожній канон? Засіяти

```bash
nysh canon check                       # «канону в просторі ще немає» — засівати
nysh canon import <дерево.ged> --dry-run
nysh canon import <дерево.ged> --authority MyHeritage
```

Імпорт лише в **порожній** канон, злиття немає. Факти приходять як
`hypothesis` із цитатою на сам файл: дерево з іншої програми є переказом
джерел. `--trust-tree` — лише якщо людина прямо сказала вірити дереву.
GEDCOM немає — перші картки пишеш руками з поля `kin` профілю.

## Крок 1 — прочитати канон ПЕРЕД внесенням

```bash
nysh text grep "<регекс прізвища чи імені>" --where canon
```

і відкрити картки осіб, яких стосується знахідка. Уже є — додаєш **цитату** до
наявного факту, а не новий факт і не нову особу-двійника.

## Крок 2 — межа: що вирішує людина

* «Це наш рід», «це та сама особа», «цей кандидат не наш» — **вердикт людини**.
  Ти кладеш кандидата з кропом (`nysh text sheet`) і чекаєш.
* Підтверджене людиною йде як `confirmed`; твій власний висновок — як
  `hypothesis`, у `hypothetical_*`-зв'язках, з поясненням у `note`.
* Цифра чи дата з декоду — лише після звірки з зображенням. Не звірено — факт
  `hypothesis` з позначкою «не звірено».

## Крок 2½ — недоведене: картка гіпотези

```bash
nysh canon next                  # що вже відкрите — спершу подивитись
nysh canon new-id hypothesis     # нова картка, якщо такої гіпотези ще немає
```

* Факт `disputed`, гіпотетичне ребро, кандидат, що чекає вердикту, —
  кожне має гіпотезу: `fact.hypothesis: H…` або особа в її `about`.
* У гіпотези є `decides` — який документ чи рядок її розв'яже. Якщо назвати
  його не вдається, гіпотеза ще не сформульована.
* Хіт іде в гіпотезу, лише якщо від нього щось залежить, і не більше п'яти.
  Решта кандидатів заходу лишається у звіті й у журналі гортача.
* Вердикт людини на хіт → онови `status`, виріж хіт, а прийняте внеси фактом.
  Закрита гіпотеза мусить мати `verdict` і `reopen_if`.
* Розмова про рід → `nysh canon next --limit 3`: три рішення з кропами
  (`nysh text crop …` з відповіді), відповідь людини — одним словом.

Формат картки й правила `check` — `references/canon.md`, розділ «Гіпотеза».

## Крок 3 — доказ у стор ДО факту

```bash
nysh text crop <справа> <скан> <рядок>              # кроп рядка
nysh evidence add <кроп.png> -p <архів> --name <осмислене_ім'я>
```

Шлях із відповіді (`data/source/citations/<архів>/<ім'я>.jpg`) вписуєш у
`media[]` картки і в `note` цитати: «Звірено по кропу. Доказ: `<шлях>`».
🔴 Ніколи не цитувати кроп із теки прогону, кеш чи scratch — їх чистять.

## Крок 4 — ID і правка картки

```bash
nysh canon new-id person        # або family / place
```

Картку писати одразу: ID нічого не резервує. Ім'я файлу = `id`. Зв'язок
записується **в обох картках** (родина ↔ особа). Хибне читання виправляєш
начисто: правильне значення на місце хибного, без «було → стало».

## Крок 5 — перевірити й перебудувати

```bash
nysh canon check          # нуль помилок; попередження прочитати
nysh canon index          # база роду для дашборда, пошуку й сайту
nysh cases build
```

**Приймач:** `canon check` друкує «помилок 0», а `index` — нові числа осіб і
фактів. Попередження `one_sided` означає, що зв'язок записано лише з одного
боку; `weak_confirmed` — що `confirmed` спирається на слабку цитату;
`hyp_verdict_ready` — вердикт на хіт уже записано, а гіпотеза його досі чекає.

## Що НЕ робити

* Не вгадувати ID і не копіювати картку-заготовку, не змінивши `id`.
* Не писати факт без цитати, а цитату без `source_id` наявного джерела: спершу
  картка джерела в `sources/`.
* Не нормалізувати прізвища в одне написання — кожне написання з джерела окремим
  `names`-варіантом.
* Не редагувати `cited_by` у маніфесті доказів — його дописує `canon index`.
* Не прибирати попередження `check`, переписуючи дані «щоб мовчало»: вік батька
  72 буває правдою, а однобічний зв'язок — ні.
