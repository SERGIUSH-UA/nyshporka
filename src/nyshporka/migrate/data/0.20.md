# Міграція агента на 0.20

## Що змінилось для тебе

**Кілька справ поспіль — чергою.** Доти ти сам зшивав кроки: взяти кадри,
завести справу, прочитати, звірити повноту, віддати — і сам пам'ятав, на якому
кроці котра справа. Тепер це робить пакет:

```sh
nysh queue add DAHMO/315/8433 data/raw/dahmo_315/spr-8434   # ключ із реєстру опису або тека
nysh queue run                 # вести чергу тут, у терміналі
nysh queue                     # що на якому етапі, що лишилось, чому стоїть
```

Справа проходить етапи: кадри → паспорт → каталог → пул → читання → облік →
віддача. Що з цього зроблено, черга щоразу бере з диска, тому після обриву
(`Ctrl+C`, вимкнена машина) той самий `nysh queue run` продовжує з того етапу,
якого ще немає, і прочитаних сторінок не перечитує.

**Три відповіді на «чому справа стоїть», і жодна не зупиняє чергу:**

- *повторить сама* — хост лежить, карта зайнята, пул відсікає за темпом; у
  рядку справи стоїть час наступної спроби;
- *чекає вас* — потрібне рішення людини; у рядку є причина й точна команда.
  Не обходь її: шифру черга не вигадує, письмо справи не вгадує, неповне
  читання уривком сама не називає. Після того як причину усунуто
  (`nysh case <тека> --shifra "…"`), наступний `nysh queue run` бере справу
  далі сам;
- *відмова* — остаточно: кадрів за адресою немає, пул відхилив пакет.

**Команди рішень:** `nysh queue set <справа> --pool take|read`,
`--partial "чому"`, `--script latin|cyrillic`, `--shifra-ok`, `--share`;
`nysh queue retry <справа>`; `nysh queue drop <справа> --why "…"`.

**Зупинити:** `nysh queue stop` — доробити поточну справу й не брати
наступну; `nysh queue stop --now` або `Ctrl+C` — погасити читання зараз,
прочитане лишається.

**Пул перед читанням** черга питає лише тоді, коли це дозволено: у профілі
обміну (`nysh share setup --lookup`) або по справі (`--pool auto`). Чужий текст
вона бере замість прогону сама, тільки якщо він накриває справу й лягає на
місцеві кадри точно (`exact`); інакше справа чекає рішення людини.

**Віддача** з черги — лише для справи з `--share`, для заходу
`nysh queue run --share` або в режимі згоди «завжди».

**Читання з екрана застосунку** тепер чекає, поки карту тримає `nysh read` чи
черга: у переліку робіт стоїть «чекає на карту» з назвою справи, що її читає.

Одну справу, як і раніше, читає `nysh read <тека>`.

**Збірна тека розкладається командою.** Теку з кадрами кількох справ
(`nysh cases chain` називає ланку `bundle_folder`, `nysh share suggest` —
статус «збірна») розкладає `nysh cases split <тека> --part
"<справа>=<перший файл>..<останній файл>" …`; спершу `--dry-run`. Межі справ
називає людина або ти після перегляду кадрів — не порівну й не за числом
аркушів з опису. Кадри не копіюються, стара тека лишається; зняти —
`--undo`. Розкладати кадри по теках руками більше не треба.

**Стан справи `archived`.** Справа, чиї кадри знято з диска після звірки з
копією, у реєстрі тепер `archived`, а не `ordered`. Ознаки: `_offloaded.json`
у теці справи чи в `pages/` (з командою `restore`) або
`purged_commons_verified` у паспорті. `nysh cases show` друкує рядок «кадри на
копії» — команду повернення чи адресу Commons. `ordered` лишився тільки для
справ, яких на диску ще не було. Знімаючи кадри, паспорт справи не видаляй
ніколи — порядок у скілі `keep-records`, крок 3½. Перед кропом чи прогоном
`archived`-справи кадри повертають командою з картки; заново таку справу не
замовляють. Фільтр: `nysh cases list --state archived`.

## Що вирішує людина

- кожну справу зі станом «чекає вас»: шифра, письмо, уривок, чужий текст із
  пулу;
- чи віддавати прочитане чергою (`--share`);
- чи дозволити черзі питати пул про кожну справу.

## Як позначити пройденою

`nysh migrate --done 0.20` — після оновлення скілів і сканування пам'яті.
