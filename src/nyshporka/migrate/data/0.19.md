# Міграція агента на 0.19

## Що змінилось для тебе

**Канон роду — твоя робота.** До 0.19 документація пакета казала, що канону тут
немає і родовід веде людина. Це було помилкою: картки осіб, родин, місць і
джерел у `data/canonical/` ведеш ти, правкою файлів. Команд «додай особу» немає
навмисно; пакет дає механіку навколо правки:

- `nysh canon check` — після кожної правки (схема, зв'язки в обидва боки,
  хронологія, докази); `nysh canon index` — перебудувати базу роду;
- `nysh canon new-id person|family|place` — ID нової картки, не вгадувати;
- `nysh evidence add <кроп> -p <походження>` — доказ у стор ДО факту;
- `nysh canon import <файл.ged>` — засіяти порожній канон.

Порядок, формат і рубрика впевненості — скіл `keep-canon`. Підтверджена людиною
знахідка йде тепер не лише в сховище сторінок, а й у канон.

**Сайт роду.** `nysh site build [--public]` збирає сайт із канону; відкрита
версія без живих, і готовий HTML перевіряє сторож. Скіл `build-site`.

**MCP-сервера немає.** Усе — командним рядком: `nysh op <ім'я> --args '<json>'`,
`nysh op <ім'я> --describe`, перелік — `nysh ops`, стартовий — `nysh ops --agent`.
Імена `nysh_…` більше нічого не означають.

**Статус аркуша за замовчуванням — `partial`.** `nysh pages note` без
`--status` більше не ставить `full`. Повну вичитку позначай `--status full`
явно — і лише з повним переліком прізвищ.

**Оренда в хмарі — лише `nysh cloud go`.** `nysh cloud start` на орендному
бекенді відмовляє й називає `go`.

## Що вирішує людина

- чи засівати канон і з чого (GEDCOM чи перші картки);
- хто з осіб живий (`private: true`) — `canon check` підкаже кандидатів
  (`maybe_living`), але вирішує вона;
- чи викладати сайт і який (лише відкриту версію — в інтернет).

## Як позначити пройденою

Коли кроки вище зелені або свідомо пропущені з людиною:
`nysh migrate --done 0.19`.
