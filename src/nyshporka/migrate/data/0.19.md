# Міграція агента на 0.19

## Що змінилось для тебе

**Канон роду — твоя робота.** До 0.19 документація пакета казала, що канону тут
немає і родовід веде людина. Це було помилкою: картки осіб, родин, місць і
джерел у `data/canonical/` ведеш ти, правкою файлів. Команд «додай особу» немає
навмисно; пакет дає механіку навколо правки:

- `nysh canon check` — після кожної правки (схема, зв'язки в обидва боки,
  хронологія, докази); `nysh canon index` — перебудувати базу роду;
- `nysh canon new-id person|family|place` — ID нової картки, не вгадувати;
- `nysh evidence add <кроп> -p <походження>` — доказ у стор ДО факту;
- `nysh canon import <файл.ged>` — засіяти порожній канон.

Порядок, формат і рубрика впевненості — скіл `keep-canon`. Підтверджена людиною
знахідка йде тепер не лише в сховище сторінок, а й у канон.

**Сайт роду.** `nysh site build [--public]` збирає сайт із канону; відкрита
версія без живих, і готовий HTML перевіряє сторож. Скіл `build-site`.

**MCP-сервера немає.** Усе — командним рядком: `nysh op <ім'я> --args '<json>'`,
`nysh op <ім'я> --describe`, перелік — `nysh ops`, стартовий — `nysh ops --agent`.
Імена `nysh_…` більше нічого не означають.

**Статус аркуша за замовчуванням — `partial`.** `nysh pages note` без
`--status` більше не ставить `full`. Повну вичитку позначай `--status full`
явно — і лише з повним переліком прізвищ.

**Серія з Супряги й пошук по ній (0.19.4).** Фонд чи опис береться одним
викликом: `nysh share pull --repo RGIA --fond 592 [--opys 25] --take`; без
`--take` — огляд серії, без жодного аргументу — огляд пулу. Прийняте одразу
лежить у текстовому сторі: не запускай після прийому `nysh text index`.
Шукати по серії — `nysh text find <прізвище> --case "RGIA 592-25"`, по кількох
справах — повтори `--case`. Не ганяй `text index`/`text find` циклом по
справах окремими процесами.

**Відповідь `share.publish` і `share.suggest` (0.19.5).** Відмова воріт пулу
несе в `data.refusals` код правила й поле маніфесту (`rule`, `field`, `text`) і
`data.policy`: розрізняй відмови кодом, не текстом. `confirmed_by_state: true`
в успішній відповіді означає, що відповідь пулу загубилась, а прийняття
підтвердив запит стану — це успіх, повторювати не треба. Текст, який пул
відхилив раніше, після оновлення його воріт віддається тією самою командою
(`rejudged: true`). У рядку `share.suggest` є `pool_frames` і `pool_coverage`:
книга в пулі з покриттям 5% — уривок, а не підстава не читати справу; `None`
— пул цього не сказав, онови зріз `nysh share sync`.

**Завантажена тека — ще не справа (0.19.6).** `meta.json` у теці лишає
завантажувач; паспорт справи — `_source.json`, і пише його лише
`nysh case <тека> --shifra "…"`. Після `nysh get` читай його останні рядки:
якщо там «справу ще не зареєстровано» — виконай названу команду, звіривши
шифру (підказка зі сторінки джерела оком не звірена). Де обірвано ланцюг по
всьому простору — `nysh cases chain` (`--json` для машинного розбору); у
`nysh doctor` це рядок «Ланцюг справи».

**Число кадрів при пакуванні й прив'язка за id (0.19.7).** `nysh share pack`
без числа кадрів справи відмовляє: назви його (`--frames N`, з каталогу чи
опису — не число прочитаних сторінок) або, якщо взяти нізвідки,
`--frames-unknown "чому"`; число не вигадуй. Після `share pull --take` дивись
`renamed` у відповіді: стільки сторінок чужого тексту перейшло на імена
місцевих кадрів (лише при `exact` за id джерела). У відповіді пошуку по всьому
простору читай `reach`: справи без жодного прогону й недосяжні корені поза
пошуком, і «не знайшлось» про них нічого не каже.

**Оренда в хмарі — лише `nysh cloud go`.** `nysh cloud start` на орендному
бекенді відмовляє й називає `go`.

**Порожнє завантаження — помилка.** `nysh get`, що не приніс жодного кадру,
виходить з кодом 1; не читай це як збій мережі — справа, найімовірніше, не
оцифрована. Раннер читання відмовляє, якщо в теці два файли одного кадру.

## Що вирішує людина

- чи засівати канон і з чого (GEDCOM чи перші картки);
- хто з осіб живий (`private: true`) — `canon check` підкаже кандидатів
  (`maybe_living`), але вирішує вона;
- чи викладати сайт і який (лише відкриту версію — в інтернет).

## Як позначити пройденою

Коли кроки вище зелені або свідомо пропущені з людиною:
`nysh migrate --done 0.19`.
